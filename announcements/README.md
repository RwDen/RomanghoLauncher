# 로망호 런처 공지

런처는 이 폴더의 `index.json`과 공지별 Markdown 파일을 공개 주소에서 읽습니다. 관리자 툴박스의 **공지 관리** 탭에서 작성하고 게시하면 런처를 다시 배포하지 않아도 반영됩니다. 실제 공지는 아직 등록하지 않았습니다.

## 표시와 갱신

- 고정 공지 우선, 이후 최초 게시일 최신순입니다. 메인에는 3개, 전체 보기에는 모든 공개 공지를 표시합니다.
- 시작 시와 표시 중 5분마다 갱신합니다. 연결이 끊기면 마지막 정상 목록과 이미 읽은 본문을 사용합니다.
- 숨김은 다음 성공적인 목록 갱신부터 적용됩니다. 공개 저장소의 숨김 파일은 비밀 문서가 아닙니다.
- 제목, 분류(공지/점검/업데이트/이벤트), 고정 여부, 본문을 입력합니다. 날짜·ID·개정번호는 툴박스가 생성합니다.

## 파일 형식 (schemaVersion 1)

목록 최상위 필드는 `schemaVersion`(1), `revision`(목록 변경 식별자), `items`(공지 배열)입니다. 각 항목은 `id`, `title`, `category`, `publishedAt`, `updatedAt`, `pinned`, `visible`, `revision`, `content`, `sha256`을 갖습니다. 날짜는 UTC 오프셋을 포함한 ISO 8601입니다. 본문 파일은 `{id}-r{revision}.md` 형태이며 `sha256`은 UTF-8 본문의 SHA-256 소문자 64자리입니다.

본문은 문단, #/##/### 소제목, **굵게**, - 목록, [링크](https://example.com)를 지원합니다. HTML은 일반 텍스트로 표시하며 웹 링크만 열 수 있습니다. 본문 30,000자/128 KiB, 목록 200개/256 KiB 제한입니다.

## 게시 방식

본문 수정 시 새 개정 파일을 추가하고 목록을 함께 하나의 Git 커밋으로 갱신합니다. 기존 본문은 보존합니다. 강제 브랜치 덮어쓰기는 사용하지 않습니다. 동시 변경은 비교 후 초안 기준을 갱신하거나 최신 공개본을 다시 불러오세요.

초안·로컬 게시 이력·인증 정보는 이 저장소에 올리지 않습니다. 게시용 인증은 관리자 PC에서만 사용하며 Windows DPAPI로 보호됩니다. 선택한 저장소에 대한 Contents 읽기·쓰기 권한이 필요한 GitHub fine-grained personal access token을 툴박스 **게시 연결**에서 입력합니다. 채팅에 토큰을 보내지 마세요. 일반 사용자 런처에는 토큰이 필요 없습니다.

[GitHub 토큰 설정 안내](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)

연결 전에도 초안 작성·자동 저장·미리보기·선택한 초안의 ZIP 내보내기가 가능합니다. 예약 게시와 이미지 첨부는 현재 지원하지 않습니다.
